# Frozen proposed item HTTP/SQLite API

This is read-only project context, not an output target. Implement exactly four
ESM files: src/validation.mjs, src/store.mjs, src/router.mjs, src/server.mjs.
Use Node24 builtins and literal static imports only. No package/dependency,
dynamic loader, network client, subprocess, handwritten test or extra output.
Libraries are safe to import; only server.mjs's explicit CLI entry starts a server.

## Data

Item is exactly {id,name,quantity}. id is generated by SQLite INTEGER PRIMARY
KEY AUTOINCREMENT, positive safe integer. name is a string; use standard JS
String.trim(), then require1..80 Unicode code points, valid Unicode (no lone
surrogate), no U+0000. Uniqueness is case-sensitive (SQLite BINARY): Alpha and
alpha differ. quantity is Number.isSafeInteger,0..9007199254740991. Unknown
input keys, arrays/null instead of objects, booleans/strings instead of quantity
are invalid. Client cannot supply id. Zero quantity is valid.

The only application table is items(id INTEGER PRIMARY KEY AUTOINCREMENT,
name TEXT NOT NULL UNIQUE, quantity INTEGER NOT NULL). Enforce CHECK constraints
in SQLite too: positive safe id; name.trim()===name, no NUL and1..80 code points;
integer quantity0..9007199254740991. SQL trim(name,chars) may use char() concatenation
for ECMAScript whitespace:9,10,11,12,13,32,160,5760,8192..8202,8232,8233,8239,
8287,12288,65279. SQLite length(name) counts Unicode code points when NUL is forbidden.
INTEGER affinity alone does not prohibit fractional quantity: use STRICT or
typeof(quantity)='integer' CHECK. Keep completed writes persistent in supplied DB.

## HTTP

Bind exactly127.0.0.1:18080; never hostname, wildcard, IPv6 or another listener.
All responses have application/json (optional charset=utf-8), complete UTF8 JSON,
no extra keys. GET /health returns200 {"status":"ok"}.
GET /items returns200 [items ordered by ascending id].
POST /items accepts exactly {name,quantity}; returns201 created item.
GET /items/:id returns200 item or404 {"error":"not_found"}.
PUT /items/:id is FULL replacement {name,quantity}; returns200 item with same id,
or404 not_found. DELETE /items/:id returns200 {"deleted":id}, or404 not_found.
POST /batch accepts exactly {items:[1..8 item inputs]}; one SQLite transaction,
returns201 {items:[created items in input order]}. A failure leaves every row
unchanged: duplicate existing/within-batch name409 {"error":"duplicate_name"};
invalid input400 {"error":"invalid_input"}. Uniqueness conflict for single
POST/PUT also409 duplicate_name. Missing target404 precedes possible rename conflict.

Decimal id URL is canonical positive safe integer (no zero/leading zero/sign/
fraction/encoded component). Invalid id400 invalid_input. Unknown route404
not_found; unsupported method for known route405 {"error":"method_not_allowed"}
with Allow (GET for health, GET/POST for items, GET/PUT/DELETE for item,
POST for batch). Any query string400 invalid_input. URL byte limit1024.
POST/PUT/batch require Content-Type application/json (optional UTF8 charset),
otherwise415 {"error":"unsupported_media_type"}. Body maximum4096 raw UTF8 bytes,
otherwise413 {"error":"body_too_large"}; malformed JSON, invalid UTF8 or an empty
required body400 invalid_input. Validation and failed batch cannot mutate DB.
Unexpected internal failure500 {"error":"internal_error"}; do not leak source/SQL.

## Module interfaces and CLI

validation.mjs exports normalizeItemInput(value), parseItemId(raw),
normalizeBatchInput(value). Return canonical values (batch returns input array);
invalid input throws an Error with status400 and code='invalid_input'.
store.mjs exports createStore(dbPath), returning synchronous list/get/create/
replace/remove/createBatch/close methods. get and replace return null for missing;
remove returns boolean; conflicts throw Error status409/code='duplicate_name'.
Only createBatch performs the all-or-none transaction. Store is backed by node:sqlite,
never a JSON file/in-memory substitute. Router exports createRouter(store), an
async Node http request handler. server imports store/router and exports no side effect.

Run Node24 src/server.mjs --db /tmp/intentsmith-http-items.sqlite --host 127.0.0.1
--port 18080; flags are explicit and unique. No defaults silently change them.
Process ENV is {}. On SIGTERM close listener and store and exit cleanly; do not
spawn descendants. A second process given same DB must reopen existing rows.
