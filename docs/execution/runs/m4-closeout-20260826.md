## Produkční cesta

1. `LearningPatternProducer` přijme pouze validní succeeded
   `ProjectChangeResult` a uloží same-project observation s exact evidence.
2. Dvě různé execution identity stejného canonical patternu mohou vytvořit
   pending proposal. Producer jej nikdy sám neschválí ani neprovede.
3. Autentizovaný uživatel proposal explicitně schválí přes projektově vázané
   HTTP API nebo Studio command. Actor se nečte z request body.
4. `ProjectLearningContext@1` načte jen aktivní learned itemy téhož projektu,
   připne workspace revision, provenance, verzi, confidence, TTL a budget.
5. Lifecycle router předá validovaný supplement produkčnímu SPEC planneru.
   Planner musí emitovat právě jednu exact conformance položku pro každý
   dodaný learned item; chybějící, duplicitní nebo vymyšlené ID fail-close.
6. Outcome evaluator znovu porovná context proti current SQLite authority,
   uloží exact baseline a observed artifact a teprve potom measured outcome.
7. Weaken vytvoří novou verzi; rollback odstraní runtime vliv a delete uzavře
   chain tombstonem. Auditní historie a evaluation artifacty zůstávají.

## Co E2E skutečně dokazuje

`tests/m4-learning-journey-e2e.test.js` používá reálný global isolated
migration runner, SQLite repository, Code Intelligence producer, application
service, workspace-revision provider, `ProjectLearningContext` a produkční
`ProjectLifecycle.startSpec()`. Pouze odpověď planner modelu je deterministický
fake. Sada nemá síť, server, Ollamu ani GPU.

Journey dokládá dvě různé approved změny → pending proposal se dvěma sources →
baseline bez learned contextu → user approval → active item verze 1 → exact
context injection → observed conformance → durable measurement
`0 → 10000`, sample size 1 → odmítnutí invented ID → rollback → nulový další
vliv → delete tombstone. Cizí projekt zůstává prázdný.

## Přiznané hranice pro review

1. Výsledek `0 → 10000` je úzká exact-contract conformance metrika nad jedním
   deterministickým vzorkem. Není to sémantický model benchmark ani důkaz
   obecného zlepšení kvality plánů.
2. Delete je autoritativní terminální tombstone a odstraňuje runtime vliv;
   fyzicky nemaže append-only auditní historii ani evaluation artifacty.
3. Nová M4 cesta je same-project. Historický `CrossProjectLearner` je default
   off a vrátí data jen po explicitním opt-in; M4 nepřidává cross-project UI
   ani automatic retrieval.
4. Learned item může ovlivnit pouze bounded project context pro planner.
   Nemůže měnit permission, code ani config a producer nemá effect authority.
5. HTTP evidence je lokální authenticated route kontrakt a owned server smoke,
   nikoli remote-companion nebo internet-facing readiness.
6. M4 nevydává deterministický fake planner za Ollama/model evidence a nemění
   model binding, GPU stav ani modelovou frontu.

## Provozní hygiena

Implementace ani closeout nespustily Ollamu, GPU nebo externí síť a neupravily
cizí checkout, proces ani GPU frontu. Dependency tree byl do izolovaného M4
worktree dodán reflink kopií a je ignorovaný. Nic nebylo pushnuto.
