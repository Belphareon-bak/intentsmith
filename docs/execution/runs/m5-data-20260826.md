## Dodaný kontrakt

- V2 backup je immutable, časově unikátní a vzniká přes privátní partial
  adresář, fsync a atomický rename.
- `metadata.json` váže přesný seřazený seznam `schema_migrations`, SHA-256
  manifest všech payload souborů a jejich společný fingerprint.
- Automatický restore vlastní pouze `c3.db`. Konfigurace, skills a specialists
  jsou archivní evidence a nejsou automaticky zapisované přes release code.
- `POST /api/system/restore` je fail-closed online hranice s typed
  `DATABASE_RESTORE_REQUIRES_OFFLINE`; zapisovací autoritu má pouze offline CLI.
- CLI před mutací ověří úplnost a hash každého payloadu, SQLite `quick_check`,
  shodu DB migrací s metadaty a kompatibilitu s migracemi aktuálního releasu.
- Restore lease je vázaný na Linux PID + `/proc` start time. Databázový opener
  respektuje živý lease a restore navíc odmítne DB otevřenou kterýmkoli
  viditelným procesem podle device/inode.
- Před atomickou výměnou aktuální DB vznikne immutable `pre-restore-*.db`
  bezpečnostní kopie. V1 backup lze vypsat, ale bez autentizovaného manifestu
  jej automatický restore odmítne.

## Round-trip a negativní důkazy

Pozitivní test založil projekt, konverzaci a zprávu, vytvořil V2 backup,
poškodil aktuální databázi, provedl offline restore a porovnal přesné DB bajty
i logický obsah. Archival-only skill a specialist byly přítomné a hashované v
manifestu, ale nebyly automaticky zapsané zpět.

Negativní případy ověřily, že současný stav se nezmění při chybějícím,
poškozeném či přidaném payloadu, při neznámé migrační identitě, online pokusu,
otevřené DB, živém restore locku a legacy V1 formátu. CLI pozitivní běh vrací
jediný JSON dokument bez absolutních cest.
