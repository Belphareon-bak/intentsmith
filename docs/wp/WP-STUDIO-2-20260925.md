# WP-STUDIO-2 — nové Studio nad stávajícím backendem

Autorita: zadání operátora 24.–25. 9. 2026 a [Decision 049](../decisions/049-studio-2-ui-and-source-control.md).
Vstup: `e9dcf52b` (`work/studio-activity-20260923`, obsahuje nasazené `72247a49`).
Stav: **UPŘESNĚNÝ KONTRAKT / IMPLEMENTACE NEOVĚŘENA**. Operátor 2026-09-25
upřesnil D1 a D2: nejnovější kompatibilní Theia; v běhu nejvýš jedno UI;
po potvrzené paritě nové UI nahradí klasické.

## Výsledek pro uživatele

Studio vypadá jako člen rodiny ShellSmith/SystemSmith a pracuje se v něm
podle prototypu: libovolně mnoho relací v očíslovaných záložkách, jedna až tři
vedle sebe, každá s vlastním terminálem a logem; sekce jako jednotný katalog
s detailem po straně; soubory relace a správa zdrojů v pravém panelu; původní
styly a volby vzhledu. Všechno funguje proti stávajícímu backendu; nové je
jen API správy zdrojů.

Podrobnosti: [UI-SPEC](../studio2/UI-SPEC.md), [REUSE-MAP](../studio2/REUSE-MAP.md),
[CONNECTORS](../studio2/CONNECTORS.md), [SCM](../studio2/SCM.md),
[THEMES](../studio2/THEMES.md).

## Jak to udělat s nejmenší prací

1. **Hostitel zůstává.** Theia, Electron shell, preload, capability transport,
   `desktop-runtime.mjs` a instalace releasů zachovají své chování. Pro aktuální
   Theiu se smí změnit sestavení a balení bez oslabení bezpečnostní hranice (D1).
2. **Nové rozšíření vedle starého.** `intentsmith-studio2` se přidá jako další
   závislost `applications/electron`; klasické UI zůstává dostupné jen do parity.
   Volba „Studio 2 / Klasické Studio" připojí k layoutu nejvýš jedno UI.
   Přepnutí nejprve odpojí původní UI a pak připojí zvolené (D2).
3. **Klientské moduly se používají přímo:** `ws-client.js`, `event-bus.js`,
   `agent-client.js`, `terminal-client.js`, `work-activity.js`,
   `@intentsmith/protocol`. Nové UI jim dodá tvar relací, jaký čekají.
4. **Logika z monolitu se kopíruje, ne přesouvá**, dokud staré UI existuje.
   Kopie dostane testy se stejnými tvrzeními jako originál. Ve starém souboru
   se před paritou smí upravit pouze životní cyklus připojení; funkční logika
   a její testy zůstanou nedotčené. Jedenáct testů se přesměruje v S2-7.
5. **Vzhled z prototypu:** tokeny `docs/studio2/design/tokens.css` se použijí
   tak, jak jsou; struktura komponent kopíruje prototyp.
6. **Backend jen jednou:** konektor správy zdrojů (S2-6) podle vzoru
   `/api/development/*`; ostatní obrazovky používají existující API.

Technika nového rozšíření: JS přímo v `lib/` (CommonJS), React z
`@theia/core/shared/react`, jeden full-window widget; komponenty v malých
souborech, CSS přes tokeny. Žádný `tsc -b` ani nová build konvence
(`DIRECTION.md` 2026-08-07, `docs/dev-checklist.md`).

## Etapy

Každá etapa je samostatně spustitelná, má ukázku v UI a končí zeleným
ověřením. Pořadí: S2-U → S2-0 → S2-1 → (S2-2, S2-3, S2-4) → S2-5 → S2-7;
backendová část S2-6 smí běžet souběžně od S2-1, její UI až po S2-4.

### S2-U — aktuální hostitel

- Převést sestavení na Theiu 1.76.0, React 19 a Node 24; všechny balíky
  `@theia/*` sjednotit a aktualizovat lockfile. Kořenový runtime a instalátor
  musí používat Node 24; testy backendu se ověří i po přestavbě nativních modulů.
- Zachovat Electron/capability vstupy v novém bundleru a převést odstraněné
  ReactDOM API ve stávajícím UI na React 19; chybějící vstup musí shodit build. Ověřit produkční build, instalaci, zabalené vstupy a skutečný
  Electron boundary journey.
- **Pozitivní test:** Studio se skutečným backendem načte autorizovaný lokální
  požadavek a renderer získá správné preload API.
- **Negativní test:** cizí origin, chybné oprávnění, nepovolený cíl a chybějící
  build vstup selžou stejně jako na vstupní verzi.
- Pokud migrace neprojde, zůstává S2-U `BLOCKED` s přesnou příčinou a nepoužije
  se neověřený build 1.76.0. Další etapy smí běžet na 1.74.1; jejich konečné
  přijetí vyžaduje rozhodnutí o verzi.

### S2-0 — základ a měření

- Za běhu zjistit, která z 18 dalších rozšíření mají viditelný příspěvek;
  výsledek jako návrh dispozice pro operátora (REUSE-MAP §6). Nic se nevyřazuje.
- Kostra `intentsmith-studio2`: titulní lišta, navigace, stavová lišta, prázdný
  střed; tokeny, 7 stylů, lokální písma a zmenšené tapety; volba UI.
- Brána volby se uplatní **před načtením modulu klasického UI** i při startu,
  obnově layoutu a přepnutí. Klasický `chat-panel-module.js` spouští transport,
  časovače a odběry událostí už při vyhodnocení modulu; samotné odpojení
  widgetu nebo zakrytí CSS proto nestačí. Přepnutí smí obnovit renderer:
  nejprve skončí starý renderer a jeho odběry, pak se načte právě zvolené UI.
  Obnovený layout nesmí znovu připojit widget neaktivního režimu.
- Změřit výchozí stav: čas do `ready`, paměť rendereru, přepnutí sekce.
- **Ukázka:** volbou se přepne na Studio 2 ve všech stylech a zpět, Klasické
  beze změny.
- **Pozitivní test:** všech 11 kombinací stylu a tématu má kompletní sadu
  tokenů; volba UI přežije restart.
- **Negativní test:** bundle ani CSS neobsahují `fonts.googleapis.com` ani jiný
  vzdálený zdroj; se zvolenou Klasickou se Studio 2 nepřipojí k layoutu;
  se zvoleným Studiem 2 se nepřipojí klasický widget ani po obnově layoutu;
  v žádném okamžiku nejsou připojená obě UI ani zdvojené odběry událostí.

### S2-1 — relace a sloupce

- `session-store.js`: N relací, převod `intentsmith-session-state` (v1) na v2
  s rozložením sloupců; starý klíč zůstává čitelný pro Klasické.
- Záložky s čísly, 1–3 sloupce, výběr relace ve sloupci s výměnou, posuvníky,
  fokus; zprávy s časovou osou, skladatel, karta schválení; spodní část
  sloupce (terminál, log, průběh, audit, problémy); stavová lišta.
- **Ukázka:** šest relací, tři sloupce; dvě konverzace pracují souběžně,
  v třetí se schválí M2 změna; restart obnoví záložky a sloupce.
- **Pozitivní testy:** převod relací; výměna relací mezi sloupci; výstup
  terminálu dorazí do sloupce podle `reqId`; M1 tah v jednom sloupci
  neblokuje jiný.
- **Negativní testy:** zavření záložky nikdy nepřesune cizí aktivní transport
  (stejné tvrzení jako `ide-workspace.test.js`); karta schválení neukáže úspěch
  bez terminálu M2; odpojení WS ukáže stav a žádný falešný úspěch; zavření
  sloupce nezruší běžící tah.

### S2-2 — katalogy a detaily

- **Pozitivní testy:** data sekcí odpovídají API (fixture backend); dlaždice a

- **Negativní testy:** detail neexistující položky ukáže prázdný stav, ne chybu;

### S2-3 — vzhled a nastavení

- **Ukázka:** přepnutí každého stylu a volby se projeví hned v celém UI;
  po návratu na Klasické zůstanou jeho hodnoty.
- **Pozitivní testy:** převod každého starého klíče; kontrast `--text` a
  `--faint` ≥ 4,5:1 ve všech kombinacích.
- **Negativní testy:** automatická politika instalací ani gitu nejde zapnout
  přes obecné nastavení; neplatná hodnota v uloženém nastavení nespadne a

- Backend podle [SCM](../studio2/SCM.md) §2–§4, UI podle §5.

- **Testy:** SCM §6 (hooky, `GIT_*`, digest, špinavý strom, rozcházení,

### S2-7 — nahrazení klasického UI

- Parita podle UI-SPEC §13 a všechny správné funkce vstupní verze potvrzené
  v reálném Studiu; 11 testů přesměrováno se stejnými tvrzeními a ostatní
  konzumenti starého UI inventarizováni. Po přijetí operátorem se odstraní
  runtime závislost klasického UI a volba Klasické Studio. Staré UI se pak
  nenačítá, nepřipojuje ani nepoužívá jako fallback; uživatelská data
  zůstávají čitelná v novém UI.
- **Negativní test:** balík aplikace neobsahuje klasický UI entrypoint,
  žádný klasický widget se neobnoví a žádný test nezávisí na jeho kódu.

## Ověření

Z kořene checkoutu:

```sh
(cd intentsmith-ide && corepack yarn build)       # produkční build + verify-m1-consumer-build
node tests/studio2-<etapa>.test.js                # testy etapy
node tests/m1-studio-client.test.js               # připnutý klient beze změny
node tests/ide-workspace.test.js
node tests/m2-lifecycle-studio-surface.test.js
node tests/studio-electron-boundary.e2e.js        # skutečný Electron, capability hranice
npm run test:registry                             # nové testy registrované
npm run test:deterministic                        # celý offline/database profil
```

Úplný profil nesmí přidat FAIL; známý stav vstupu je 366 PASS / 1 FAIL
(nezměněná Gate 0 pečeť) / 0 BLOCKED. Ukázka každé etapy běží ve skutečném
Electronu s vlastní DB, bez modelového provideru; kontrolované události nejsou
důkaz živé inference.

**Měřítka L3:** čas do `ready`, paměť rendereru a přepnutí sekce nesmí být
horší než výchozí měření z S2-0 o víc než 10 %.

## Stop podmínky

Kromě CONTRACT §11 se práce zastaví, když:

- by bylo nutné změnit `ws-client.js`, M1 wire, `@intentsmith/protocol`,
  capability transport nebo preload;
- by připnutý test musel oslabit tvrzení, být přeskočen nebo přeznačen;
- by se mělo vyřadit rozšíření bez schválené dispozice;
- by SCM potřebovalo ukládat credentials nebo pouštět síť mimo povolené hostitele;
- měření L3 překročí limit a příčina není v rozsahu etapy;
- nasazení by mělo přerušit běžící GPU práci.
