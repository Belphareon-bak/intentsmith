# WP — poslední krátká uživatelská oprava v kontextu chatu

**Autorita:** požadavek operátora z 30. 9. 2026 dokončit funkční chat a ověřit auto-context, navazující na WP `WP-CHAT-ANSWER-SUMMARY-BOUNDARY-20260930.md`. Výchozí revize je čistá `09e72b74939175eabb9a8a8d9733178a7adbb4fd`; změna vzniká v odděleném worktree a nemění běžící backend, produkční DB, GPU ani integrační root.

**Nález:** finální modelový požadavek při 4K okně, 2 263 B aktuálním dotazu a 983 B serializovaném trvalém souhrnu zachoval starou hodnotu `A=3` ze souhrnu, ale tiše vynechal pozdější krátkou uživatelskou opravu `A=4` (110 B jako JSON řádek). Volání poskytovatele přesto proběhlo s `num_predict=431`. Samotné upřednostnění uživatelských turnů neřešilo případ, kdy plný souhrn spotřeboval celý vyhrazený prostor.

**Vlastněné cesty:** `src/chat/handlers/decisions.js`, `tests/m1-chat-contract.test.js`, tento WP. Nejnovější předchozí uživatelský turn se při serializované délce nejvýše 512 B rezervuje celý spolu s trvalým souhrnem. Pro `CONVERSATIONAL` smí jeho zachování snížit skutečný výstupní strop až k existující hranici 256 tokenů; finální systémová instrukce se stále ustálí podle skutečného `num_predict`. Pokud se oba nutné bloky nevejdou, handler skončí před providerem interním `ChatProcessingError` se `sourceErrorType=ANSWER_RECENT_USER_CONTEXT_TOO_LARGE`. Pokud se nevejde ani samotný souhrn, zachová se `ANSWER_CONTEXT_SUMMARY_TOO_LARGE`. CODE a ostatní intenty nemění výstupní strop, ale mohou skončit typovaně, pokud by se krátký předchozí uživatelský turn jinak ztratil.

**Kontrolní důkaz:** M1 smluvní sada na Node 24.21.0 má 45 PASS / 0 FAIL. Nový finální provider-body scénář se souhrnem `A=3`, opravou `A=4` a dlouhým dotazem vyžaduje celý souhrn, celou opravu, správné pořadí, aktuální dotaz na konci a shodu slovního cíle s `num_predict`. Těsnější varianta vyžaduje nula provider volání a přesný interní `sourceErrorType`. Hraniční test používá přesně 512 B serializovaný krátký turn a 513 B delší turn: první se zachová celý, druhý zůstává volitelnou zkracovanou historií. Řízená rekonstrukce se vstupy z dřívějšího soukromého běhu sady 85 (`09247504`) ověřila, že opakovaný dlouhý předchozí uživatelský turn 2 502 B stále projde: aktuální vstup 2 499 B, celý summary JSON 1 034 B, `num_predict=288`, plán 57 slov a jedno kontrolované provider volání. Rekonstrukce není nový živý modelový běh.

**Reziduální riziko:** ochrana je úmyslně omezená na jediný nejnovější předchozí uživatelský turn do 512 B. Starší oprava nebo delší uživatelský turn, které ještě nejsou v trvalém souhrnu, se mohou z konečného promptu zkrátit nebo vynechat. Tento WP nedokazuje obecnou faktickou správnost modelu ani živé auto-context chování. Veřejné M1 HTTP/WS odpovědi podle stávající smlouvy zveřejňují jen obecné `CHAT_PROCESSING_FAILED`; přesný `sourceErrorType` zůstává interní diagnostikou. Nezávislá revize, integrace a nový živý běh jsou další brány.
